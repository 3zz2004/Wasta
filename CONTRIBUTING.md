# Contributing

Thanks for helping. A few things make reviews fast.

## Layout

```
data/      governorates and mobile prefixes, the single source of truth
spec/      JSON test vectors both packages must pass
js/        the npm package (TypeScript)
python/    the PyPI package
scripts/   code generation and release helpers
assets/    README banner and demo, generated by scripts/readme-art
```

## Fixing a bug

1. Add the failing case to the right file in `spec/`.
2. Fix it in **both** `js/` and `python/`. A change that lands in one language only will fail CI.
3. If you touched `data/`, run `node scripts/sync-data.mjs` and commit the generated files.

## Running the checks

```bash
# JavaScript
cd js
npm install
npm run typecheck
npm test

# Python
cd python
pip install -e . pytest ruff mypy
ruff check . && ruff format --check .
mypy src
pytest
```

## Releasing

1. Bump the version in `js/package.json`, `python/pyproject.toml` and `python/src/wasta/__init__.py`, and add an entry to `CHANGELOG.md`.
2. Tag and push: `git tag v0.2.0 && git push --tags`.

The release workflow publishes to npm and PyPI through trusted publishing: both registries are set up to accept releases from `.github/workflows/release.yml` in this repository, so no tokens are stored anywhere. A version that is already published is skipped.

## Ground rules

- No runtime dependencies.
- Error codes are part of the public API. Adding one is a minor release; renaming one is a major release.
- Arabic output must be correct Arabic. If you're unsure about a grammatical form, say so in the PR and cite a source.
